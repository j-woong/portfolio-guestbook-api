# 03. 도배 방지와 관리자 삭제

| 키워드 | 한 줄 설명 |
|---|---|
| Rate limit | 정해진 시간 안에 같은 요청을 반복하지 못하게 막는 것 |
| ConcurrentHashMap | 여러 스레드가 동시에 써도 안전한 Map |
| `compute` | 한 키에 대해 "읽고 → 판단하고 → 쓰기"를 한 번에 처리하는 메서드 |
| X-Forwarded-For | 프록시가 원래 방문자 IP를 적어 주는 헤더 |
| 상수 시간 비교 | 비교에 걸리는 시간이 값에 따라 달라지지 않는 비교 |

## 공통 개념: 로그인이 없는 API를 지키는 방법

방명록은 로그인이 없다. 그래서 "누가 쓰는지"는 IP로, "누가 지울 수 있는지"는 서버만 아는 키로 구분한다.

## 도배 방지 `WriteRateLimiter`

- IP마다 마지막 작성 시각을 Map에 기록한다. 30초가 안 지났으면 `false`를 돌려주고 서비스가 429를 던진다.
- 동시에 두 요청이 오는 경우가 문제다. "기록을 읽고 → 30초 지났는지 보고 → 새 시각을 쓰는" 사이에 다른 요청이 끼어들면 둘 다 통과할 수 있다. `compute`는 같은 키에 대해 한 번에 한 스레드만 실행되므로 하나만 통과한다. EFY에서 결제 승인이 두 번 오는 문제를 락으로 막은 것과 같은 종류의 문제다.
- 검증에 실패한 요청(400)은 컨트롤러에서 끝나므로 횟수에 들어가지 않는다.
- 기록이 1만 건을 넘으면 30초가 지난 기록을 지운다.
- 한계: 서버 메모리에 저장하므로 서버가 여러 대면 정확하지 않고, 재시작하면 초기화된다. 서버가 늘어나면 Redis 같은 공용 저장소로 옮겨야 한다. X-Forwarded-For는 클라이언트가 꾸밀 수 있어서 완벽한 방어는 아니다.

## 관리자 삭제 `DELETE /api/guestbook/{id}`

- 요청 헤더 `X-Admin-Key`가 환경변수 `ADMIN_KEY`와 같을 때만 삭제한다. 다르면 403.
- `ADMIN_KEY`가 비어 있으면 어떤 키를 보내도 403이다. 설정을 빠뜨렸을 때 아무나 지울 수 있는 상태가 되지 않게 했다.
- 비교는 `equals` 대신 `MessageDigest.isEqual`을 쓴다. `equals`는 다른 글자를 만나면 바로 끝나서, 응답 시간으로 키를 한 글자씩 추측할 여지가 있다.
- 키는 코드나 Git에 넣지 않고 배포 환경변수로만 설정한다.

```bash
curl -X DELETE https://<서버 주소>/api/guestbook/3 -H 'X-Admin-Key: <관리자 키>'
```
